# 定制化产品 Listing 健康检查器 — 完整方法论

## 运行环境（box）

- 脚本目录：`amazon-listing-health-checker/`（`browser_utils.py` / `fetch_amazon_page.py` / `fetch_amazon_search.py`）
- Python：`python`
- 抓取方式：curl（已加 `--compressed`，否则亚马逊返回 gzip 乱码）+ BeautifulSoup；邮编切换已修复
- 报告目录：`reports/brands/{品牌名或ASIN}/listing-health-check/`
- 被验证码拦截（`page_status=captcha`）时：改用 box 浏览器（已登录亚马逊买家账号）打开页面人工读取，不要猜
- 已知小问题：`fetch_amazon_search.py` 能正确找到 ASIN 排名，但搜索结果里的**标题字段常为空**；判断可见性只看位置/是否出现即可
- 实测（2026-10）：B0XXXXXXX2 页面抓取成功（标题、$19.95、BSR、4.1 星/17 评、有货）；搜索 "custom leather journal" 自然位第 38 名

## 1. 技能定位

### 核心理念
**通过 curl + BeautifulSoup 抓取亚马逊服务端渲染的 HTML，不借助任何 API 或第三方数据工具。**

原因：我们要验证的是"消费者打开亚马逊能看到什么"。任何 API 返回的数据都可能与前台页面不一致（缓存、区域差异、权限差异）。这个技能的价值就在于**所见即所得**。

亚马逊商品页面的核心数据（标题、价格、卖家、BSR、评论等）全部在服务端渲染的 HTML 中，无需 JavaScript 执行。curl 配合正确的浏览器 Headers 可稳定获取完整页面（~2.4MB HTML）。

### 定制化产品适配

> ⛔ **本 Skill 专为定制化产品（Custom/Personalized）设计**，判断标准与标品存在关键差异：

| 检查项 | 标品 Skill 判断 | 本 Skill 判断（定制化产品） |
|--------|----------------|---------------------------|
| 购物车状态 | Add to Cart + Buy Now = ✅ | **Customize Now** = ✅；有 Add to Cart 反而 ⚠️ |
| 卖家信息 | FBA = ✅ 优选 | **FBM** = ✅ 正常（定制品卖家直发） |
| 配送信息 | Prime ✅、≤7天 = ✅ | **无 Prime** = ✅ 正常；7-21天 = ✅ 正常 |

### Script Directory
脚本位于 `amazon-listing-health-checker/`：
- **browser_utils.py** — 通用网页抓取模块（curl 封装、站点配置、反爬检测），其他 Skill 可复用
- **fetch_amazon_page.py** — 商品页面抓取，提取 9 项检查数据 + **Customize Now 检测**，输出 JSON
- **fetch_amazon_search.py** — 搜索结果页抓取，检查 ASIN 搜索可见性，输出 JSON

### 工作流位置
```
定制化产品上架流程：
  Listing-Skill → 上架
      → 【Listing-Health-Checker：上架验收】
      → 人工修复 → 复检

日常运营：
  定期巡检 → 【Listing-Health-Checker】→ 发现问题 → 人工修复 → 复检
```

### 上下游
| 方向 | 技能 | 关系 |
|------|------|------|
| 上游 | Listing-Skill | Listing 创建完成后需要验收 |
| 下游 | 人工修复 | 检查出问题后需要人工介入 |
| 下游 | 复检（再次调用本技能） | 修复后重新验证 |

## 3. 检查项详细定义

### 3.1 页面可访问性
**检查内容**：页面是否正常渲染商品信息。

| 状态 | 判断条件 |
|------|----------|
| ✅ 正常 | 页面包含商品标题、图片、价格等核心元素 |
| ❌ 异常 | 出现狗狗页面（Dog page）、404、"Looking for something?"、"Currently unavailable"、验证码页面 |

**常见异常场景**：
- ASIN 被下架 → 狗狗页面或 "Currently unavailable"
- ASIN 被合并到其他变体 → 自动跳转
- 区域限制 → "This item does not ship to your location"

### 3.2 价格与优惠
**检查内容**：当前售价、划线价、折扣、优惠券。

| 状态 | 判断条件 |
|------|----------|
| ✅ 正常 | 有明确售价显示 |
| ⚠️ 需关注 | 价格与预期差异较大（需用户判断） |
| ❌ 异常 | 无价格显示、显示 "See price in cart"、或价格为 $0 |

**记录字段**：
- 当前售价
- 划线价（List Price / Was Price）
- 折扣百分比
- 优惠券（Coupon）金额或百分比
- 是否有"Subscribe & Save"折扣

### 3.3 卖家信息（Buy Box）— ⭐ 定制化适配

**检查内容**：Sold by 和 Ships from 信息。

| 状态 | 判断条件 |
|------|----------|
| ✅ 正常 | Sold by 显示为用户指定的卖家名称 |
| ✅ 正常 | Ships from 显示为**卖家名称**（FBM 直发 = 定制化产品正常模式） |
| ⚠️ 需关注 | Ships from Amazon（FBA）— 定制化产品不应走 FBA |
| ❌ 异常 | Sold by 不是指定卖家（Buy Box 被抢） |

> ⛔ **定制化差异**：标品以 FBA（Ships from Amazon）为优选，但定制化产品由卖家直发制作，Ships from 显示卖家名 = 正常。如果反而显示 Ships from Amazon，说明发错了 FBA 非定制版本。

**记录字段**：
- Sold by：卖家名称
- Ships from：发货方
- 是否为 FBA（Ships from Amazon）
- ⭐ FBM 判断：定制化产品 FBM = ✅ 正常

### 3.4 购物车状态 — ⭐ 定制化适配

**检查内容**：是否有 Customize Now / Add to Cart / Buy Now 按钮。

| 状态 | 判断条件 |
|------|----------|
| ✅ 正常 | 显示 **Customize Now**（定制化产品的正确按钮） |
| ⚠️ 需关注 | 只有 Add to Cart + Buy Now，**未检测到 Customize Now**（可能定制化功能未激活） |
| ⚠️ 需关注 | 显示 "See All Buying Options" |
| ❌ 异常 | 无购买按钮，或显示 "Currently unavailable" |

> ⛔ **定制化差异**：标品判断 Add to Cart + Buy Now = 正常。但定制化产品的正确购物流程是 **Customize Now** 按钮引导用户进入定制编辑器，然后才能加入购物车。如果只有 Add to Cart 没有 Customize Now，说明定制化配置可能未正确生效。

### 3.5 配送信息 — ⭐ 定制化适配

**检查内容**：预计送达时间和 Prime 状态。

| 状态 | 判断条件 |
|------|----------|
| ✅ 正常 | 有明确的预计送达日期，**无 Prime 标识**（FBM 直发正常） |
| ✅ 正常 | 配送时间 7-21 天（定制品制作+发货需要更长时间） |
| ⚠️ 需关注 | 有 Prime 标识（定制化产品不应有 Prime，可能配置错误） |
| ⚠️ 需关注 | 配送时间超过 21 天 |
| ❌ 异常 | 无配送信息 |

> ⛔ **定制化差异**：标品以 Prime + ≤7天送达为优选。但定制化产品通过 FBM 直发，不走 Prime 物流，且需要制作时间，7-21天配送属于正常范围。如果反而有 Prime 标识，说明可能错误地使用了 FBA 标品发货。

**记录字段**：
- 预计送达日期
- 是否有 Prime 标识
- 配送费用（免费/具体金额）
- ⭐ 定制化配送时间判断：≤21天 = ✅ 正常；>21天 = ⚠️ 偏慢

### 3.6 类目与节点
**检查内容**：
1. 搜索栏旁的大类（department selector）
2. 面包屑导航中的销售节点路径（通常在主图上方）

| 状态 | 判断条件 |
|------|----------|
| ✅ 正常 | 能正常显示类目信息 |
| ⚠️ 需人工确认 | 类目信息显示正常，但需人工确认是否为期望的节点 |

**记录字段**：
- 搜索栏大类名称
- 面包屑完整路径

> 注意：类目节点的"正确性"需要人工判断，技能只负责抓取和展示，不做自动判断。

### 3.7 BSR 排名
**检查内容**：Best Sellers Rank 在各层级类目中的排名。

| 状态 | 判断条件 |
|------|----------|
| ✅ 正常 | 有 BSR 排名数据 |
| ⚠️ 需关注 | 排名显著下跌（需历史对比） |
| ❌ 异常 | 无 BSR 排名（可能表示商品未正常入库或类目异常） |

**记录字段**：
- 每个层级的类目名称 + 排名数字

### 3.8 差评监控
**检查内容**：首页评论中的差评（1-3 星）数量和内容。

| 状态 | 判断条件 |
|------|----------|
| ✅ 正常 | 首页 0 条差评 |
| ⚠️ 需关注 | 首页 1-2 条差评 |
| ❌ 异常 | 首页 3 条及以上差评 |

**记录字段**：
- 总评分（星级）
- 总评论数
- 首页差评条数
- 每条差评的：星级、标题、简要内容、日期
- 差评趋势判断：首次检查标注「首次检查，无历史对比基线」

### 3.9 搜索可见性
**检查内容**：用核心关键词搜索后，商品是否出现在搜索结果首页。

| 状态 | 判断条件 |
|------|----------|
| ✅ 正常 | 在首页自然位找到 |
| ⚠️ 需关注 | 仅在广告位找到，自然位未找到 |
| ❌ 异常 | 首页完全未找到（可能被压制或搜索不可见） |

**关键操作**：
- 搜索时确保选择 "All Departments"
- 区分自然位（Organic）和广告位（Sponsored）
- 记录具体位置编号

## 4. 执行步骤（详细）

### Step 1：参数解析与准备
1. 从用户输入中提取 ASIN、站点代码、品牌名、核心关键词
2. 验证 ASIN 格式（10 位字母数字）
3. 根据站点代码查找域名和默认邮编
4. 如果用户未提供站点代码，默认使用 US
5. 构建商品页面 URL：`https://{domain}/dp/{ASIN}`

### Step 2：抓取商品页面
运行 `fetch_amazon_page.py` 脚本抓取商品页面并提取结构化数据：

```bash
python amazon-listing-health-checker/fetch_amazon_page.py {ASIN} --site {站点代码}
```

脚本输出 JSON，包含以下字段：
- `page_status`：页面状态（ok / dog_page / unavailable / captcha / fetch_failed）
- `title`：商品标题
- `price`：当前售价、划线价、折扣、优惠券
- `seller`：sold_by、ships_from
- `cart`：add_to_cart、buy_now、see_all_buying_options、⭐ **customize_now**
- `delivery`：配送文本、Prime 标识
- `category`：搜索栏大类、面包屑路径
- `bsr`：各层级排名和类目
- `ratings`：评分星级、评论总数
- `reviews_on_page`：首页评论详情（星级、标题、日期、内容、是否差评）
- `variants`：变体信息
- `stock`：库存状态
- `anomalies`：异常提示列表

### Step 3：解析检查结果
将脚本返回的 JSON 数据逐项对照第 3 节的判断标准，为每个检查项标记状态：
- ✅ 正常
- ⚠️ 需关注
- ❌ 异常

**⭐ 定制化专属判断逻辑**：
- `cart.customize_now == true` → 3.4 购物车 = ✅
- `cart.customize_now == false && cart.add_to_cart == true` → 3.4 购物车 = ⚠️ "未检测到 Customize Now"
- `seller.ships_from` 不含 "Amazon" → 3.3 卖家 = ✅ FBM 正常
- `delivery.prime == false` → 3.5 配送 = ✅ 正常（无 Prime 符合定制化预期）
- `delivery.prime == true` → 3.5 配送 = ⚠️ "定制化产品不应有 Prime"

对于脚本未能提取的字段（值为空或缺失），标注为「⚠️ 未能获取」，不做推测。

### Step 4：搜索可见性检查
⛔ **仅在用户提供了核心关键词时执行本步骤。**

对每个核心关键词，运行 `fetch_amazon_search.py` 脚本：

```bash
python amazon-listing-health-checker/fetch_amazon_search.py "{keyword}" {ASIN} --site {站点代码}
```

根据第 3.9 节的判断标准标记搜索可见性状态。

**注意**：多个 ASIN 搜索同一关键词时，只需抓取一次搜索结果页。

### Step 5：生成健康检查报告
按照第 5 节的报告模板，将所有检查结果整理为 Markdown 报告。

**总体评估逻辑**：
- 🟢 全部通过：所有 9 项均为 ✅
- 🟡 需关注：有 ⚠️ 但无 ❌
- 🔴 有异常：有任何一项 ❌

### Step 6：保存报告
将报告保存到：
```
reports/brands/{品牌名或ASIN}/listing-health-check/{YYYY-MM-DD}_{ASIN}_健康检查报告.md
```

如果无法从页面确定品牌名，使用卖家名称或 ASIN 作为目录名。

### Step 7：输出摘要
在终端向用户输出：
1. 总体评估状态（🟢/🟡/🔴）
2. 异常项和需关注项的简要列表
3. 报告文件的保存路径

## 6. 数据诚信规则
本技能严格遵守以下数据原则：

1. **数据来源唯一**：所有信息来自亚马逊官网页面抓取（curl + BeautifulSoup），不使用 Sorftime MCP 或其他任何第三方数据工具。
2. **不推测未获取信息**：脚本无法提取的字段，标注为「⚠️ 未能获取」，绝不编造。
3. **标注数据时效**：报告中明确标注检查时间，说明"结果仅代表检查时刻的页面快照"。
4. **区分事实与判断**：
   - 页面抓取到的原始信息 = 📊 数据事实
   - 基于检查结果给出的建议 = 💡 分析推断
5. **差评趋势需历史对比**：首次检查只记录快照，不做"是否新增差评"的判断。

## 7. 局限性与应对
| 局限 | 说明 | 应对方式 |
|------|------|----------|
| JS 动态内容 | curl 获取服务端渲染 HTML，JS 动态加载的内容可能缺失 | 如关键信息缺失，标注「⚠️ 可能因动态加载未获取」 |
| 反爬机制 | 亚马逊可能返回验证码或简化页面 | 脚本自动检测验证码，报告中标注「❌ 被亚马逊拦截，建议手动检查」 |
| 地域差异 | 未实际设置邮编，可能影响价格和配送显示 | 在报告中说明使用的邮编和站点 |
| 搜索个性化 | 搜索结果受算法影响 | 注明"搜索结果为特定时刻快照" |
| Customize Now 检测 | 定制化按钮的 HTML 结构可能因页面版本变化 | 使用多选择器 + 文本兜底双重检测 |

## 8. 使用场景

### 场景 1：新品上架验收
定制化产品上架 24-48 小时后，检查 Customize Now 按钮是否正常、FBM 发货是否正确、类目是否到位。

### 场景 2：日常巡检
每周检查核心 ASIN 的健康状态，监控差评趋势和搜索可见性。

### 场景 3：异常排查
销量下降时，排查是否 Buy Box 被抢、Customize Now 按钮消失、或被错误切换到 FBA。

### 场景 4：批量检查（多 ASIN）
依次对每个 ASIN 执行 Step 1-7，共享同一关键词的搜索结果页。
